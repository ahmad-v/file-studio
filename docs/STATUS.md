## Native catalogue workspace

The GUI starts on a Catalogue page with native file/folder pickers, read-only path-fragment search over a saved SQLite snapshot, a sortable paginated Localwright table for results (50 rows per page) and history (20 rows per page), and refresh that appends a complete scan. A dedicated create flow selects a source folder and a new SQLite path, scans in the background, supports cooperative cancellation, rejects overwrite through the existing no-clobber writer, and opens the newly created catalogue history. Each result can be inspected when the user chooses its source folder; the read-only view revalidates the relative path and displays the existing inspector report (hashes, available timestamps, bounded hex sample, and supported PNG properties). Refresh progress is indeterminate during directory traversal and determinate while SQLite rows are added; polling runs only while a job is active, and cancellation remains available. The **Analyze directory usage** action adds a bounded bar-chart preview of the 20 largest top-level groups, including root-level files, without modifying source files. History shows deltas only for matching source identities. Selecting two history rows fills the comparison scan IDs, and users can compare any two retained snapshots entirely offline; the report shows added, removed, size-changed and same-size paths and explicitly identifies whether both snapshots have the same stable source identity. The Operations page retains all registered File Studio operations. Unit tests cover bounded result/history/usage parsing, chart fraction calculation, table sorting, selection, pagination behavior, input validation, settings compatibility, native non-Unicode paths and the progress display model. Native visual/usability, screen-reader and accessibility review remain pending.

## Known gaps

The Catalogue workspace additionally scans a selected source folder for matching BLAKE3 content-hash groups, displays up to 20 groups at a time with up to eight paths per group, and never deletes or moves files. This is a live read-only scan rather than disconnected catalogue analysis; candidate hashing is limited to 1 GiB. The new duplicate-report parser and native workflow tests are local-only until the corresponding PR checks pass.

Signature identification is a limited prefix test, not exhaustive or format validation. Inaccessible paths and safety limits mark scans partial; partial JSON reports cannot be loaded as complete inventories and partial scans do not create catalogue snapshots or removal counts. The local SQLite catalogue records append-only history and supports disconnected path search. Unix scan-root identity uses filesystem device plus inode; Windows now uses volume serial plus root-directory file index through the `file-id` crate. Targets without stable identity use full-rescan baselines. Refresh still traverses the complete tree and does not use filesystem change journals. Same-size content changes are not detected. The native result inspector reads only after the user chooses a source folder and revalidates every path component, but filesystem replacement races cannot be ruled out on all platforms. Catalogue database paths are canonicalized after final-file symlink checks to support macOS symlinked temporary-directory parents. PNG sanitation removes only documented text and EXIF chunks. EXIF tag reading now uses the bounded kamadak-exif parser for JPEG, TIFF, HEIF/HEIC/AVIF, PNG, and WebP; this does not decode XMP/IPTC generally. JPEG sanitation removes recognized EXIF APP1, standard XMP APP1, and Photoshop APP13 segments before the first scan while preserving ICC APP2 and scan bytes; other metadata sanitation, later/proprietary segments and complete metadata verification remain unsupported. Digital signature verification remains unavailable. Versioned directory backup is implemented on a development branch and awaits hosted verification. It is not full system recovery. It compares open file handles with the cross-platform `same-file` library and rechecks size/modification time; this is best-effort race detection, not race-free traversal or an atomic snapshot. Restore does not preserve ownership, permissions, timestamps, ACLs, extended attributes, hard-link relationships, or symbolic links. The embedded SHA-256 manifest is unsigned integrity data, not authentication. Age identity generation currently creates an unencrypted private key file; keep it in a user-controlled location and maintain a secure backup. Unix permissions are checked. Windows restricts identity and decrypted output paths to the user profile and relies on inherited directory ACLs, which are not independently audited. Age encryption does not authenticate the sender. File encryption and decryption stream files up to 4 GiB and do not overwrite outputs. Directory ZIP and TAR routes skip symlinks, empty directories and filesystem metadata, and cap file count at 4,096, per-file size at 32 MiB and total input/expanded bytes at 128 MiB; TAR archive input itself is capped at 160 MiB and paths at 1,024 bytes. TAR header checksums do not cover payload content. GZIP routes handle single-file streams (including concatenated read members), cap compressed and expanded content at 1 GiB, and omit source filesystem metadata. GZIP CRC is not authenticity. SHA-256 manifests are integrity records, not authenticated signatures. File metadata comparison cannot detect every concurrent modification or path race.

The five-target hosted build/test/preview matrix passed for the age encryption increment. Device and full packaging lifecycle verification remain open. See [verification evidence](VERIFICATION.md) and [dependency review](DEPENDENCIES.md).

## CI workflow architecture

Ordinary pull requests and pushes to `main` use the Linux x64 `Check` job for formatting, locked all-target checks/tests, strict Clippy, metadata validation and registry validation. Markdown-only changes retain the same check context while skipping Cargo work. `Integration` covers default GUI and headless tests plus virtual-display launch on manual dispatch or the `integration` PR label. `Native platform validation` covers all five target build/test jobs on manual dispatch or the `native-validation` PR label. `Distribution preview` manually produces optimized unsigned portable evaluation bundles only; installable package workflows remain blocked by unresolved identities, build-tool provisioning and device acceptance. Weekly/manual Security and dependency review runs RustSec and generates CycloneDX and declared-license/notice inventory evidence. Its generated license report is not a legal approval. This CI refactor is awaiting its initial hosted run.
