# Dependencies

Cargo manifests list the exact direct requirements. The committed lockfile records the resolved versions and registry checksums. Builds use Rust 1.89.0 from `rust-toolchain.toml`; this minimum is required by the bundled `rusqlite 0.43.0` persistent catalogue engine. The CI checkout action is pinned to its upstream v4.2.2 commit.

The persistent catalogue uses `file-id 0.2.3` (`MIT OR Apache-2.0`) to obtain the Windows volume serial number and directory file index through its safe API. The crate uses the Win32 handle APIs internally and falls back to a full rescan whenever an identifier cannot be read. Unix catalogue identity continues to use the standard library's device and inode metadata. The ID identifies a source on one machine at a time; filesystems may reuse identifiers after deletion or reformatting.

The File Studio GUI depends directly on the shared Iced version for its catalogue workspace and uses `rfd 0.15.4` with the XDG desktop portal backend for native file/folder dialogs. This keeps the dialogs native and avoids requiring GTK development libraries in Linux builds. The existing Localwright operation contracts and File Studio route handler remain the processing boundary.

File encryption uses the exact direct dependency `age 0.11.5` (`MIT OR Apache-2.0`) with default features disabled. It implements the established age X25519 file format; the application does not implement cryptographic primitives. This X25519-only integration avoids enabling the upstream crate's unrelated OpenSSH and newer recipient features. The lockfile records its transitive dependency checksums. Review the generated CI license inventory and update this summary if the resolved graph changes.

A preliminary RustSec review used advisory database revision `c9f6c91a44dbad9d71742329e9df061279f9c4be`. The pinned Localwright revision uses Iced’s Tiny Skia software renderer and removes the affected `lru 0.12.5` dependency path (RUSTSEC-2026-0002 and RUSTSEC-2026-0253). Full license review, SBOM and native dependency review remain open.

The persistent catalogue uses `rusqlite 0.43.0` with its bundled SQLite source (`libsqlite3-sys 0.40.0`) and `tempfile 3.19.1` for private staging before no-clobber publication. Rusqlite is MIT; SQLite's upstream project is public domain. Bundling avoids an external SQLite installation and fixes the supported Rust minimum at 1.89. Catalogue databases are capped at 64 MiB, opened read-only for search/history, and versioned with application and schema IDs. Final license/native asset review remains open.

Single-file GZIP operations use the existing locked `flate2 1.1.11` dependency with the Rust-native `zlib-rs` backend. The bounded uncompressed TAR workspace uses `tar 0.4.46` (`MIT OR Apache-2.0`) with default features disabled; its reader/writer operates on standard I/O streams and does not add a compression backend. The resolved lock graph adds `filetime 0.2.30` (`MIT OR Apache-2.0`) and reuses the existing `libc` and `cfg-if` packages. TAR payloads do not have a standard integrity checksum.

This branch pins Localwright core/UI to reviewed immutable revision `8354a5359bb3cb7723b52d341f9158536525c8a4`, which includes the earlier optional SVG-to-PDF figure export support. File Studio does not enable the `figure-pdf` feature. Its package graph is recorded in the lockfile, but it is not activated in the File Studio binary.

On 2026-11-27, `cargo +1.89.0 audit --file Cargo.lock` found no vulnerability advisories. It reported eight unmaintained crates with no fixed versions: `basic-toml 0.1.10`, `instant 0.1.13`, `pin-utils 0.1.1`, `proc-macro-error2 2.0.1`, `rustybuzz 0.14.1`, and `ttf-parser` 0.20.0, 0.21.1 and 0.25.1. These remain dependency-monitoring items; the current advisory output contained no security vulnerability finding.

EXIF field inspection uses `kamadak-exif 0.5.5` (BSD-2-Clause), a pure-Rust parser supporting JPEG, TIFF, HEIF/HEIC/AVIF, PNG and WebP containers. The inspected package version is beyond the fixed version for RUSTSEC-2021-0143 (fixed in 0.5.3); this is a bounded parser of untrusted files and remains covered by the scheduled advisory audit. The package's license file is collected by the generated dependency-notice workflow. No image codec or external executable is added.

The versioned directory-backup route reuses the existing `zip 9.0.5` Deflate archive implementation and `sha2 0.10.9` SHA-256 primitive. It adds the small `same-file 1.0.6` dependency (Unlicense/MIT) for stable cross-platform open-handle identity comparisons; it adds no cryptographic algorithms or external runtime engines. The embedded checksum manifest is intentionally unsigned; it detects accidental data corruption but does not authenticate a backup.

Detached signatures use `ed25519-dalek 2.1.1`, `rand_core 0.6.4`, and `hex 0.4.3`. They sign a versioned, domain-separated message containing the streamed file length and SHA-256 digest. Public-key fingerprints must be trusted out of band. Private-key JSON is not passphrase-encrypted; restrictive file permissions do not protect against a compromised account, backup, or device. PAR2 workflows use `parmesan-par2 0.6.0` (MIT) for packet handling and Reed–Solomon recovery, with a bounded one-file creation route. The crate's verification and repair APIs do not support responsive cancellation. Its Rust sources are compiled natively; prebuilt executables are not assumed for every architecture.
